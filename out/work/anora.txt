e:Tc1a,<p>The problem: College students report worsening mental health during exam seasons, but existing journaling apps route sensitive entries through cloud services before insights surface. The privacy cost of the insight is too high.</p>
<p>The constraint: On-device inference had to fit within a 10MB app bundle and stay under 200ms on a mid-range Android phone. The model also had to generalize across three languages: English, Hindi, and Marathi, with zero cloud round-trips.</p>
<p>What I built: Anora stacks a quantized INT8 MentalBERT encoder inside a TFLite flatbuffer, running entirely in the Flutter process via the <code>tflite_flutter</code> plugin. The FastAPI backend handles only encrypted sync payloads and aggregate analytics. I implemented federated learning with secure aggregation using TensorFlow Federated so the shared model improves without any device exposing its journal entries.</p>
<p>The architecture splits responsibilities cleanly: device-side inference returns sentiment, emotion tags, and reflection prompts locally. The server stores only encrypted blobs keyed by device salt. The shared aggregator model trains on synthetic gradients that are aggregated before hitting the coordinator.</p>
<p>A second tradeoff: I shipped with English-only prompts first to hit the inference budget. Hindi and Marathi support landed six weeks later as a smaller update, which meant early adopters got a less useful experience.</p>

<p>What broke: The first federated round used a fixed learning rate of 0.01, which caused client drift on devices with sparse journaling patterns. The model overfit to a handful of enthusiastic early testers and degraded sentiment tagging for infrequent writers. Rolling back to per-client adaptive rates fixed it, at the cost of two weeks of delayed training cycles.</p>
<p>The second failure was more expensive: the initial TFLite delegate allocation was static, so on low-RAM phones the app crashed during onboarding. The fix required switching to dynamic delegates and deferring model load until after the first successful sync. That pushed the first release back by ten days.</p>
<p>What I'd do differently: Start the multilingual prompt generation earlier. The English-only launch created churn that would have been avoidable with a language-agnostic prompt template system from the beginning.</p>
