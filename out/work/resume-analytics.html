AI-Powered Resume Analytics Platform

Parses 1,000+ unstructured resumes into structured data with NER and serves a RAG chatbot for hiring team queries.

RUNTIME
Sep 2024 - Dec 2024
FORMAT
Python / FastAPI / LLM REST / PostgreSQL
RUN ON
AWS EC2
STATUS
Shipped
CREDIT
Solo

The problem: Campus recruiters at a tier-2 engineering college in Mumbai receive 1,000+ resumes in a single placement cycle, all in PDF format with inconsistent templates. Hiring teams spend hours extracting skills, experience, and contact details manually.

The constraint: The NER model had to handle Indian naming conventions, universities with varied spellings, and non-standard date formats, all without a GPU.

What I built: The platform ingests PDFs through PyMuPDF, sends them to an LLM REST endpoint configured for structured extraction, and writes the results into a PostgreSQL database with JSONB columns for skills and experience. A LangChain-powered RAG chatbot lets recruiters ask natural-language questions like "Show me candidates who know Python and React and graduated after 2022."

The architecture separates the ingestion pipeline (batch processing) from the query layer (real-time), and I implemented a caching layer for repeated entity extractions to keep the OpenAI cost under $15 per 100 resumes.

Numbers:

Metric Value Baseline
Resumes processed 1,243 0 (manual)
Average extraction accuracy 92.1% 67.3% (regex baseline)
Parse time per resume 4.2s 22 min (manual)
Recruiter query response 1.8s 8 min (manual search)
Cost per batch of 100 $14.20 $350 (manual labor)

What broke: The first deployment failed on resumes with two-column layouts because PyMuPDF concatenated both columns into a single text stream, which broke the entity boundaries. The fix required switching to a layout-aware PDF parser (pdfplumber) and adding a preprocessing step that detects column gutters.

The second issue was less obvious: Indian university names vary wildly in their English spellings. "Fr. Conceicao Rodrigues College of Engineering" sometimes appears as "FCRCE" or "Rodrigues College." The NER model kept missing these, so I added a fuzzy string matcher against a seeded university registry with 200+ Indian institutions.

What I'd do differently: Build the university registry before the ingestion pipeline. The entity accuracy was bottlenecked on domain-specific normalization, and I kept bolting fixes onto the extraction layer.
